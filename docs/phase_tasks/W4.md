secrets.py: contains_secret(text) -> bool and redact_secrets(text) -> str.
Detect at minimum:
- Discord bot tokens (three dot-separated base64url segments, first decodes to
  a snowflake; also match the `MT`/`MF`/`Nz`-prefixed 24+ char first segment).
- OpenAI/Anthropic/Pinecone style keys: sk-, sk-ant-, sk-proj-, pcsk_, pplx-,
  gsk_, AIza, ghp_, github_pat_, xoxb-.
- `Authorization: Bearer <token>` and bare `Bearer <token>`.
- Assignments: (api[_-]?key|apikey|token|secret|password|passwd|pwd|
  access[_-]?key|client[_-]?secret) followed by =/:/ => and a value of 8+ chars.
- AWS access key ids (AKIA/ASIA + 16 chars) and 40-char AWS secret values.
- Generic high-entropy opaque strings: 32+ chars, mixed case + digits, no
  spaces, Shannon entropy above a threshold you justify in a comment. Tune this
  so that ordinary prose, DOIs, arXiv ids, long URLs, and paper titles do NOT
  trigger it. Write tests proving those negatives.
redact_secrets replaces the matched span with "[REDACTED]" and never returns
any part of the original secret.

capture.py: CaptureDecision and MemoryCapturePolicy exactly as contracted.
evaluate_user_message must:
- Reject immediately when contains_secret() is true. reason="secret_detected".
  redacted_text="". The reason string and any log line must NOT include the
  message text or the matched substring. Assert this in a test.
- Reject stack traces (a line matching `Traceback (most recent call last)`,
  `File "..." , line N`, or 3+ lines ending in an exception class name).
- Reject shell/log dumps (3+ lines starting with $, >, #, or a timestamp
  prefix) and raw PDF-ish text (very long single paragraph over 2000 chars with
  no first-person marker).
- Reject non-durable chatter: greetings, thanks, acknowledgements, questions
  (text ending in ? with no durable statement), and messages under ~15
  characters.
- Accept and classify durable first-person statements into a MemoryClass:
    preference        "I prefer", "I like", "I'd rather", "I usually"
    rejected_idea     "I don't want to pursue", "stop working on", "drop",
                      "no longer interested in", "not pursuing"
    goal              "my goal is", "I want to", "I'm trying to", "aiming to"
    constraint        "I only have", "I can't use", "limited to", "must not",
                      "budget", "deadline"
    research_interest "I'm interested in", "I'm researching", "I work on",
                      "I care about"
    project_decision  "I decided", "we decided", "going with", "settled on"
    tool_preference   mentions a tool/library with a preference verb
    workflow_preference mentions how they want work done ("always run tests
                      first", "keep commits small")
    research_direction "next I want to explore", "planning to look at"
    temporal_plan     statements with an explicit future time reference
  Ambiguous but clearly durable first-person statements fall back to
  MemoryClass.PREFERENCE rather than being dropped.
- redacted_text is the whitespace-normalized message, with redact_secrets
  applied defensively even on the accept path.
- When constructed with enabled=False, every message is rejected with
  reason="capture_disabled".
evaluate_assistant_message ALWAYS returns should_store=False with
reason="assistant_output_never_stored". Scientific claims generated by the
assistant must never become user memory.

Tests must include an explicit adversarial case: a message containing a
realistic-looking (but fake) Discord token and a `sk-` key, asserting
should_store is False, that the token substring appears nowhere in the
CaptureDecision (check every field), and that redact_secrets removes it.
