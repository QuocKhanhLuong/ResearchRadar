Sections in this EXACT order, with these EXACT headers:
  SYSTEM RULES
  USER MEMORY (ADVISORY — NOT SCIENTIFIC EVIDENCE)
  EXPLICIT PROJECT MEMORY (CANONICAL USER/PROJECT STATE)
  STORED SCIENTIFIC EVIDENCE (CANONICAL)
  LIVE DISCOVERY EVIDENCE (METADATA/ABSTRACT-LEVEL ONLY)
  QUESTION
Empty sections are omitted entirely except SYSTEM RULES and QUESTION.

SYSTEM RULES must state, in substance:
- USER MEMORY is what the user has said about themselves. It is advisory
  context, never scientific support, and never evidence that a claim is true.
- Never present a user hypothesis, belief, or preference as a published result
  or as something "the literature shows".
- Never claim the literature contains no work on a topic; the corpus here is
  partial and bounded.
- Cite ONLY the paper ids and gap ids that appear in the evidence sections,
  using their exact ids.
- Distinguish stored PaperCard evidence (analysed full text) from
  abstract/metadata-only evidence, and say explicitly when the answer rests
  only on abstract/discovery-level metadata.
- Do not invent deep experimental claims (numbers, ablations, benchmark
  results) from metadata alone; if the question needs that depth, say the
  answer requires reading the papers.
- When EXPLICIT PROJECT MEMORY and USER MEMORY conflict, EXPLICIT PROJECT
  MEMORY wins; say so rather than silently picking one.
- Say plainly when the available evidence is insufficient.

Budget the prompt: cap abstracts (roughly 800 characters, truncated at a word
boundary with an ellipsis), cap the number of items rendered per section, and
cap user-memory facts. Put the caps in a small frozen dataclass so they are
testable and adjustable.

Render each user-memory fact with its temporal validity when present, so an
older superseded preference is visibly older rather than collapsed with the
current one.

Tests — these are the strict source-boundary tests and are the point of this
task:
- A user-memory fact whose text mimics a citation stays inside the USER MEMORY
  section; the section header ordering and the "advisory, not evidence"
  language are present verbatim.
- No paper id outside packet.allowed_paper_ids appears anywhere in the rendered
  prompt.
- A packet with only discovery items renders the discovery section, omits the
  stored section, and the rules text about abstract-only evidence is present.
- A packet with a project whose rejected_ideas contradicts a user-memory fact
  renders both, with the project section marked canonical and outranking.
- Section order is exactly as specified; assert on the index positions of the
  headers in the rendered text.
- Truncation is applied and never splits mid-word.
