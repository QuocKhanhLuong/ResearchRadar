MEMORY CONTAMINATION
- Assistant-generated scientific text is never written as an episode.
- A message that is only a question writes no episode.
- An episode write is never attempted on the LLM-failure path.

MENTION FILTERING
- @everyone, @here, and a role mention containing the bot do not admit.
- A message from another bot that DOES mention the bot is still rejected.
- With DISCORD_ALLOWED_CHANNEL_IDS set, a mention in another channel is
  rejected before any service call.
- With DISCORD_OWNER_USER_ID set, a mention from another user is rejected.

DUPLICATE LIVE INGESTION
- The same topic asked twice does not create duplicate canonical paper rows.
- One chat turn triggers at most ONE ingestion call (assert the call count).
- The discovery limit is hard-clamped: request 50, assert <= 12 reach the
  provider layer.

EVENT-LOOP SAFETY
- Assert that ChatService.chat does not perform a blocking call on the running
  loop. Practical approach: install a fake repository whose synchronous methods
  assert they are NOT executing on the event loop thread (compare
  threading.get_ident() against the loop thread's ident captured in the test),
  and drive one full chat turn through it.
- Assert no unbounded thread spawning: run N=20 sequential chat turns and check
  threading.active_count() does not grow monotonically.

CREDENTIAL SAFETY
- A fake credential in a user message reaches neither the memory store, nor
  caplog records, nor any raised exception's string form, nor ChatResponse.text.
- MemoryStatus and any /memory-status style output never contain a credential
  or raw graph internals.

BACKEND OUTAGE BEHAVIOUR
- Memory outage, semantic outage, ingestion outage, and LLM outage each degrade
  rather than raise, and each sets the documented response flags.
